# 法律检索协议（平台中立）

> 本文件替代旧版对特定平台工具名的硬编码依赖。
> **任何智能体环境均可执行**：有 MCP 用 MCP，无 MCP 用通用网络检索，都必须做时效核验。

---

## 序、最高优先级铁律（任何任务不得违反）

# 🔴 法条法律验证的取源顺序是**强制的、不可颠倒的**

```
┌─────────────────────────────────────────────────────────────┐
│ 第①优先级【唯一权威源】                                      │
│   权威源法条原文：国家法律法规数据库 / 专业法律数据库          │
│   （本技能使用方的实现方式可能是 MCP、CLI 或官方站点直取，    │
│     由本次任务开始时的能力探测决定）                          │
├─────────────────────────────────────────────────────────────┤
│ 第②优先级【内部知识库法律法规】                              │
│   自建知识库 raw/00-法律法规/ 下的法规原文                    │
├─────────────────────────────────────────────────────────────┤
│ 第③优先级【外部补充】                                        │
│   其他法律检索 MCP → 官方站点直取 → 通用网络检索              │
└─────────────────────────────────────────────────────────────┘
```

### 三条硬规则

**规则1｜先取权威源原文**
涉及法条、法律、司法解释、地方性法规的**内容与文本**，**必须先从权威源取原文**
（国家法律法规数据库或专业法律数据库）。该库由全国人大常委会办公厅主办，
是**唯一权威现行文本来源**。取法条内容与现行有效性，**先于**查内部知识库。

**规则2｜其次自建知识库**
权威源不可用、未收录、或需查本地整理材料时，**再查自建知识库**的法规原文。
知识库是**辅助定位与便捷调取**，**不得推翻**权威源的结论。

**规则3｜冲突时以权威源为准**
若知识库内容与权威源**不一致**：
- 判定依据以**权威源**为准
- 知识库差异**必须写入报告「待确认/差异」区**，标明可能需更新
- 不得为迁就知识库而采信旧法或错误文本

> ⚠️ **不可跳过第①优先级直接查知识库。**
> 知识库内容存在滞后或人工录入错误的可能（本次补验即发现知识库辅助材料与法条原文存在表述差异）。
> 反之，**权威源收录滞后时**可用知识库补充，但须标注来源等级差异。

### 工具不可用时（降级规则）

```
权威源 MCP 不可用？
  → 按第③优先级改用官方站点直取 / 通用网络检索（限定官方域名）
  → 仍取到官方原文的：在报告中记录实际渠道，按已核验处理
  → 完全取不到官方原文的：明确标注「未能使用权威源验证，仅使用知识库材料」
  → 关键定性结论标【需专业人员确认】
  → ❌ 严禁编造 MCP 调用、条文号或检索结果
```

**不得因为权威源工具缺失就跳过验证**，也不得编造条文。

> 🔴 **来源可信度与工具可用性是两个独立维度**：
> "没有接 MCP"只是**取得路径**变了，不改变官方原文本身的权威性；
> 但"没有实际取到原文"就是**未核验**，必须如实披露。二者不得混淆。

### 权威源的等价识别（跨平台）

"国家法律法规数据库"是**库名**，不同环境实现方式不同。按以下顺序识别可用权威源：

| 优先级 | 权威源类型 | 常见实现 | 说明 |
|---|---|---|---|
| **1** | **国家法律法规数据库** | MCP 配置名（如 `flk-npc`）；站点 flk.npc.gov.cn | 由**全国人大常委会办公厅**主办，唯一权威现行文本 |
| 1' | 专业法律数据库 | **北大法宝**（`pkulaw`）、威科先行 | 收录全国人大常委会公布文本，**可作等价权威源** |
| 2 | 自建知识库 | `raw/00-法律法规/` | 辅助定位 |

> ⚠️ **本文件不记录任何特定机器的环境实测结果**（连通性、工具数量、历史调用日志）。
> 工具是否可用**必须由本次任务开始时实际探测**得出——探测顺序与降级路径见第一节。
> 开发者本机的历史实测结论**不能**推定客户环境具备。

### 权威源调用范式（按实际探测到的能力选用）

> 以下为**调用方式示例**，不是"假定已连通"。仅在本次探测确认相应工具可用时使用；
> 不可用时按第一节降级路径执行，并**如实记录实际使用的渠道**。

**方式 A｜国家法律法规数据库 MCP（探测确认可用时）**

```
① flk_search(search_content="劳动合同法")
   → 返回候选列表：ID / 状态（生效中·已废止·被修订）/ 制定机关 / 公布日期 / 生效日期 / 法律性质

② flk_hit_display(bbbs="<上一步的ID>", search_content="<法条关键词>")
   → 返回命中法条原文片段

③ flk_get_detail(bbbs="<ID>")
   → 返回法规元数据 + 目录树 + 历史版本
```

> ⚠️ **务必先看"状态"字段**——同名不同状态并存是常态
> （检索"劳动合同法"可能同时返回：已废止、生效中、被修订等不同条目）。
> **必须选"生效中"的那一条**，否则会引用已废止文本。
>
> ⚠️ **MCP 服务器的函数名与工具名可能不同**（工具名与 Python 函数名不必一致），
> 且入参可能是 Pydantic 模型而非平铺 kwargs。**以本次探测到的实际 schema 为准**，
> 不照抄历史日志中的调用签名。

**方式 B｜北大法宝 MCP（探测确认可用时）**

```jsonc
// 第一步：查法规清单（可加时效/效力过滤）拿准确标题
{"title": "劳动合同法", "timeliness": ["现行有效"]}
// 第二步：逐条取原文
{"title": "劳动合同法", "tiao_num": 42}   // 42=第四十二条；2.1=第二条之一
```

返回要点：`Title`（含修正年份）、`DocumentNO`、`IssueDate`、`ImplementDate`、
`TimelinessDic`（效力状态）、`FullText`

**通用原则**：**先查清单拿准确标题与效力状态，再逐条取原文**——两步法可避免同名多版本误取。

**方式 C｜无任何法律 MCP 时（降级）**

- 直接访问官方站点取原文（如 flk.npc.gov.cn、司法部国家行政法规库、最高法官网、
  部委官网），或限定官方域名的通用网络检索；
- **仍须做到**：取到条文原文、核对效力状态、记录**实际使用的渠道与检索日期**；
- 报告中写明"本次通过官方站点直取核验"或"本次未使用权威源验证，仅使用知识库材料"，
  **不得编造**任何未发生的 MCP 调用；关键定性结论标【需专业人员确认】。

## 零、检索是强制项，不可省略

**即使内部资料已给出结论，也必须检索公开现行法做交叉核验。**

理由：劳动法规与司法解释逐年变动，模型记忆不可靠。**跳过检索 = 承诺准确性但无法保证。**

### 0.1 知识层（E1）不是结论依据 —— 自证循环禁令

本技能自带的 `dismissal-pathway.md` 与 `evidence-checklist.md` 是**基于经验与学习材料的人工总结**，
它们是**检索线索与分析框架**，**不是法律依据**。



**禁止**（自证循环）：把"技能手册说第40条要三步法"写进报告依据栏——用自己写的总结证明自己写的东西对。

**要求**：报告依据栏写《劳动合同法》第40条第2项（现行有效）。知识层只负责"提示去查第40条"，由法条原文负责定性。

**E1 的正确用法**：🔍 检索线索、🧠 分析框架、⚠️ 风险提示、✍️ 证据清单模板
**E1 的错误用法**：❌ 当依据、❌ 替代原文核验、❌ 用"手册说"说服用户

> 完整机制（元数据、confidence、失效触发、同步流程）见 `knowledge-integrity.md`。
> 每次引用 E1 内容时，**必须同时回 A1 取法条原文校验**，差异写入报告「待确认」区。

## 一、检索能力探测与取源顺序

**两条独立的线，不要混为一谈**：

1. **权威性排序**（决定"以谁为准"）：权威源 A1 ＞ 内部知识库。
2. **能力探测**（决定"实际怎么取"）：本次任务开始时**实测**当前环境有哪些检索通道可用。

### 1.1 能力探测（任务开始时执行一次）

| 探测项 | 探测方法 | 可用时的记录 |
|---|---|---|
| 法律检索 MCP | 实际列出/调用一次检索类工具 | 工具名、是否真正连通 |
| 权威法律数据库（专业库） | 同上 | 同上 |
| 官方站点直取 | 访问官方域名取一页原文 | 站点、URL、状态码 |
| 通用网络检索 | 限定官方域名检索 | 实际检索词与命中来源 |
| 内部知识库 | 查 `KB_ROOT` / `raw/` 目录 | 目录是否存在、命中条目 |

> 🔴 **不得跳过探测直接假定可用，也不得假定不可用。**
> 探测结果**如实记录**在报告的「检索方式说明」中。

### 1.2 取源顺序（权威性，不可颠倒）

| 优先级 | 能力 | 说明 |
|---|---|---|
| **1（权威源）** | **权威源法条原文**（国家法律法规数据库 / 专业法律数据库） | **唯一权威现行文本，必须优先** |
| **2** | **自建知识库法律法规** | `raw/00-法律法规/`，辅助定位与便捷调取 |
| 3 | 其他法律检索 MCP | 用于案例与深度检索 |
| 4 | 官方站点直取 | flk.npc.gov.cn、司法部国家行政法规库、最高法官网等 |
| 5 | 通用网络检索 | 限定官方域名 |

> ⚠️ **禁止**引用不存在的工具名。工具不可用时按序章降级规则处理，并在报告中说明实际检索方式。
> ⚠️ **官方原文的可信度独立于 MCP 可用性**：无 MCP 时走 4/5 取得的官方原文，
> 与有 MCP 时取得的原文**具有同等权威性**，不得因此降格为"仅知识库材料"。

## 二、来源分级（结论与依据的对应关系）

| 级 | 类型 | 用途边界 |
|---|---|---|
| **A1** | **国家法律法规数据库 / 权威法律数据库（北大法宝等）** | **法条文本与现行有效性的最高权威源，须优先使用** |
| **A** | 法律法规、行政法规、司法解释、官方案例 | 关键定性（可不可以解除、是否违法解除）**必须 A 级** |
| **B** | 官方实施资料（人社部解释、办事指南、地方高院会议纪要） | 解释落地，**不得改变上位法** |
| **C** | 公开专业参考（律所文章、专家解读） | **仅作线索**，不单独支持重大定性或放行 |
| **D** | 自媒体、二手转载 | **不引用**，仅用于发现检索关键词 |
| **E1** | **本技能实体层**（`dismissal-pathway.md` / `evidence-checklist.md`） | 🔴 **不得支撑确定性结论**——它本身就是经验总结，用它论证自己是自证循环。仅作检索线索与分析框架，凡结论依赖其中法条表述必须回 A1 取原文。详见 `knowledge-integrity.md` |
| **E2** | **企业知识库**（`user-knowledge/` 政策包） | 辅助定位，**不得推翻 A1/A 级权威源**；可抬高内控等级，不得降低法定风险 |

> 📌 取源顺序铁律见本文件**序章**。A1 > A > B > C > D，**E1/E2 为辅助层**。
> 🔴 **典型 E1 陷阱**：直接引用 `dismissal-pathway.md` 的"三步法"作为报告依据而未回查第40条原文——若法条为"经培训**或者**调整工作岗位"，而总结写成两者都需做，实操即产生偏差。
> ⚠️ 典型 D 级陷阱："孕期绝对不能解除"——法律上协商解除不受第42条限制，此说法不准确。

### 3.3.1 劳动合同法重点条款定位指引

《劳动合同法》原文在 `raw/00-法律法规/劳动用工法律法规/01_核心法律/02_中华人民共和国劳动合同法.md`，
**全文 98 条集中在一份文件内**（不拆分，便于维护）。高频条款检索位置：

| 条款 | 内容 | 用工场景 |
|---|---|---|
| 第4条 | 规章制度民主程序与公示 | 制度效力争议 |
| 第7条 | 用工关系的建立 | 事实劳动关系认定 |
| 第10条 | 书面劳动合同订立 | 未签合同/二倍工资 |
| 第19条-20条 | 试用期期限与工资 | 试用期解除 |
| **第36条** | **协商一致解除** | 协商解除（第42条不限制） |
| 第37条 | 劳动者提前通知辞职 | 员工主动退出 |
| 第38条 | 被迫解除（9种情形） | 欠薪/未缴社保 |
| **第39条** | **过错解除（6项）** | 严重违纪/严重失职 |
| **第40条** | **无过错解除（3项）** | 不能胜任/医疗期满 |
| **第41条** | **经济性裁员** | 规模裁员 |
| **第42条** | **六项不得解除情形** | 特殊员工阻断 |
| 第43条 | 事先通知工会 | 单方解除程序 |
| 第44条-45条 | 终止与顺延 | 合同到期 |
| **第46条-47条** | **经济补偿范围与计算** | N 测算 |
| 第48条 | 违法解除的后果 | 继续履行 vs 赔偿金 |
| 第82条 | 二倍工资 | 未签合同 |
| 第87条 | 违法解除赔偿金（2N） | 违法成本 |

> ⚠️ **检索提醒**：引用第42条时须逐项核对全部六项，常见错误是漏掉第1项
> （职业病危害作业未做离岗前健康检查）与第6项（法律行政法规规定的其他情形）。

### 3.4 知识库检索的三条纪律

1. **先看 YAML 效力状态字段**——知识库文件含 `效力状态` / `发文字号` / `实施日期`，先读这三个字段
2. **注意"已废止"标注**——知识库常标注新旧法对照，如"侵权责任法第6条（已废止）"，引用前必须确认
3. **知识库是辅助，不是权威**——法条的现行有效性仍须外部核验（见第四节）

## 四、外部检索：同名多版本识别（强制）

### 4.1 为什么这条最重要

劳动法领域存在**中文名称完全相同、法效不同**的多版本文件。典型：

| 名称 | 文号 | 施行 | 状态 |
|---|---|---|---|
| 劳动争议司法解释（一） | 法释〔2020〕26号 | 2021-01-01 | 现行（第32条第1款已废止） |
| **劳动争议司法解释（二）** | **法释〔2025〕12号** | **2025-09-01** | **现行最新** |
| 劳动争议司法解释（二） | 法释〔2006〕6号 | 2006-10-01 | ❌ **已被替代** |

**两者中文名只差"（一）""（二）"，仅凭名称无法区分。**

### 4.2 引用前三项核验（缺一不可）

1. **文号**：`法释〔年份〕号`
2. **施行日期**
3. **是否被新解释明文废止**

引用时**必须写出文号与施行日期**，例如：
> 依据《最高人民法院关于审理劳动争议案件适用法律问题的解释（二）》（法释〔2025〕12号，2025-09-01施行）

### 4.3 无法确认时的处理

同名多版本且无法确认 → **强制标【需专业人员确认】**，**不得单选其一**。

## 五、时效核验清单

| 项目 | 要求 |
|---|---|
| 法条版本 | 以官方现行有效版本为准，标注版本年份+效力状态 |
| **最低工资标准** | 🔄 **运行时重查**（逐年调整，不得沿用旧值） |
| **社保缴费基数上下限** | 🔄 **运行时重查**（每年7月前后调整） |
| 经济补偿封顶基数 | 🔄 运行时查当地上年度职工月平均工资**3倍** |
| 年休假天数 | 依累计工龄分档，需按现行《职工带薪年休假条例》核验 |
| 地区裁判口径 | 🔄 按用工所在地重查，不同地区差异大 |

> ⚠️ 本文件**不固化任何数值**。所有金额、天数、比例必须运行时检索获取。

### 经济补偿 3 倍封顶的核验指引

计算 N 时若员工月工资偏高，**必须先核验是否触及封顶**，否则金额会算错：

```
步骤1：查「本地区上年度职工月平均工资」
       → 检索词："{城市} 上一年度 职工月平均工资 公布"
       → 权威源：当地人社局/统计局公告、政府工作报告

步骤2：封顶基数 = 上年度职工月平均工资 × 3

步骤3：比对员工解除前12个月平均工资
       → 未超封顶基数 → 按实际工资计算（正常情况）
       → 超过封顶基数 → 按封顶基数计算，且年限最高不超过12年

步骤4：确认「月工资」口径
       → 通常指解除前12个月平均应得工资（含奖金、津贴）
       → 需按当地口径确认是否剔除加班费、特殊津贴
```

> ⚠️ **常见错误**：直接按员工工资算，不查当地社平工资。
> 员工月薪 3 万以上时，3 倍封顶会显著降低 N 金额，**必须核验**。

## 六、检索失败时的处理

| 情形 | 处理 |

## 七、地区口径的检索方法

**地区差异是劳动法最大的不确定性来源**，必须按用工所在地检索。

### 7.1 检索词模板

```
"{城市} 劳动争议 裁判指引 第X条"          → 找地方高院/中院会议纪要、裁判指引
"{城市} 中院 劳动争议 审理指引"            → 找系统性的地区口径文件
"{城市} {争议点关键词} 裁判标准"           → 针对具体争点
"{城市} 劳动争议 典型案例 {年份}"          → 找本地案例
```

### 7.2 常见地区口径文件类型

| 类型 | 示例形式 | 效力 |
|---|---|---|
| 会议纪要 | 《XX省高院劳动争议审判会议纪要》 | B级，但实践影响大 |
| 裁判指引 | 《XX市中院关于审理劳动争议案件的裁判指引》 | B级 |
| 答复/意见 | 人社部门或高院答复 | B级 |
| 典型案例 | 法院发布的本地典型案例 | C级（个案约束力） |

### 7.3 高频地区争点清单（须按当地核验）

| 争点 | 常见分歧 |
|---|---|
| 末位淘汰=不胜任？ | 深圳、四川明确不支持；部分地区口径不一 |
| 二次到期终止权 | 北京、上海有明确口径 |
| 代通知金基数 | 上海、深圳有专门口径 |
| 经济补偿封顶基数 | 部分地区按社平工资3倍执行细则不同 |
| 经济性裁员程序 | 各地对报告程序的宽严不同 |
| 严重违纪的"严重"标准 | 需看当地对违纪分级的认定尺度 |

> ⚠️ **不得跨地区套用口径**。
> 地域适用**不存在**"实际用工所在地 ＞ 劳动合同履行地 ＞ 签订地 ＞ 注册地"的通用排序：
> 实体标准按《劳动合同法实施条例》第14条判断（含"注册地标准更高且已约定则从其约定"的例外），
> 程序管辖按《劳动争议调解仲裁法》第21条等单独判断，两者不得混同。
> 详见 `jurisdiction-scope.md`。

## 九、知识材料优先与冲突处理
