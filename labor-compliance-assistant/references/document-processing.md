# 文档处理能力（可选增强）

> 本文件说明本技能可用的脚本能力。
> 🔴 **核心原则：脚本是可选增强，不是核心依赖。** 脚本失败时降级为直接读原文，**绝不阻塞主流程**。

---

## 一、能力清单

| 脚本 | 用途 | 触发时机 | 必需性 |
|---|---|---|---|
| `knowledge_sync_check.py` | 知识层**元数据体检** | 知识层更新后、例行体检 | 可选 |
| `extract_labor_terms.py` | 用工合同关键条款抽取 | 材料是合同/协议/制度时 | 可选 |
| `generate_docx.py` | Markdown → Word | 用户选形式 A 时 | 可选 |

**依赖情况**：

| 脚本 | 外部依赖 | 缺失时 |
|---|---|---|
| `knowledge_sync_check.py` | 无（纯标准库） | 人工核对元数据 |
| `extract_labor_terms.py` | 无（.docx 需 python-docx） | 直接读原文 |
| `generate_docx.py` | 需 `python-docx` | 降级为仅 Markdown，**并说明原因**；缺依赖时脚本**以退出码 1 明确声明**，不静默失败 |

## 一之二、`knowledge_sync_check.py` 的能力边界（必读）

> 🔴 **本脚本只做元数据体检，不是法律变更监控工具。**

| 它**能**做 | 它**不能**做 |
|---|---|
| 检查 frontmatter 字段是否齐全 | ❌ 联网抓取法规、发现法律是否已修订 |
| 检查 `last-checked` 日期是否可解析、是否为未来日期 | ❌ 比对知识层表述与现行法条正文是否一致 |
| 检查 `layer` / `confidence` 取值是否合法 | ❌ 判断某条法律解释是否已被推翻 |
| 检查核验时效是否超阈值 | ❌ 自动更新知识层内容 |
| 检查 E1 文件是否登记 `staleness-trigger` | ❌ 替代按 `kb-search-protocol.md` 的公开检索核验 |
| 检查 E1 文件之间的交叉引用是否存在（静态启发式） | ❌ 判定"知识层合法有效" |

> ⚠️ **「体检通过」只表示元数据自洽，不表示内容正确或法律有效。**
> 报告中不得把体检结果表述为"知识层已同步到现行法"。

## 二、`extract_labor_terms.py` 用法

### 2.1 覆盖的条款类型

| 类型 | 键名 | 检测重点 |
|---|---|---|
| 试用期 | `probation` | 期限是否超法定上限、是否二次约定 |
| 竞业限制 | `noncompete` | 期限超2年、未付补偿、违约金畸高 |
| 保密义务 | `confidentiality` | 期限、违约金合法性 |
| 违约金 | `liquidated_damages` | 是否超出第22/23条允许范围 |
| 工时与休假 | `work_hours` | 综合/不定时是否审批、加班费、年休假 |
| 社会保险 | `social_insurance` | 自愿放弃、现金折现 |
| 解除与终止 | `termination` | 末位淘汰、无需通知、三期表述过宽 |
| 送达与通知 | `delivery` | 视为送达条款 |
| 调岗与变更 | `job_change` | 单方调岗、工资另行核定、地点宽泛 |
| 规章制度效力 | `rules_validity` | 单方修改、免民主程序 |
| 录用条件 | `recruitment` | 表述模糊无法举证 |

### 2.2 命令示例

```bash
# 基本用法
python scripts/extract_labor_terms.py 劳动合同.docx

# 仅看高风险（过滤掉正常条款）
python scripts/extract_labor_terms.py 合同.txt --min-risk high

# 只抽特定类型
python scripts/extract_labor_terms.py 制度.md --type rules_validity,termination

# JSON 输出（便于后续处理）
python scripts/extract_labor_terms.py 合同.docx --json
```

### 2.3 输出解读

脚本输出的是**风险线索**，每条附带对应的**法条提示**：

```
1. [第八条 竞业限制] 乙方离职后两年内不得...甲方不另行支付经济补偿...
   🔴 高风险线索  命中：不另行支付经济补偿
     《劳动合同法》第23条：离职后的竞业限制期间，用人单位应当按月给予劳动者经济补偿...
```

> ⚠️ **法条提示是编写脚本时固化的参考值，不是实时检索结果。**
> 报告中引用前**必须回 A1 权威源核验**，这是不可省略的步骤。
> 全部提示的对应法条、适用条件与核验记录见 `references/script-clause-registry.md`。

### 2.3.1 判定规则要点（避免误读）

| 规则 | 说明 |
|---|---|
| **试用期按合同期限联合判断** | 脚本先识别合同期限（固定期限月数 / 无固定期限 / 以完成一定工作任务为期限），再按第19条算出法定上限（1/2/6 个月，或不得约定）。**合同期限未识别时不会当作"无风险"**，而是输出「无法判断，须补核合同期限」的待核验线索 |
| **在职与离职后竞业分开** | 第23条的按月补偿义务指向"**解除或终止劳动合同后**"；在职期间竞业限制依法释〔2025〕12号第14条不因未付补偿而当然无效。脚本按句中时间指向分别给提示 |
| **多标签匹配** | 同一句含多个独立义务时**全部保留**，不再只归入首个命中类型 |
| **类型关键词约束** | 每类 pattern 均含该类关键词，"竞业限制期限为五年"不会被归入试用期 |
| **未命中不等于无风险** | 表格、扫描件、图片、复杂句式均可能漏抽；未抽取到线索时脚本明确提示这一点 |

### 2.4 已知局限

| 局限 | 说明 |
|---|---|
| **正则启发式** | 非语义理解，可能漏报或误报 |
| **合同期限识别有限** | 仅识别"合同期限/合同期间+数字+单位"等常见表述；表述特殊或散落多处时可能未识别，此时输出待核验提示而非结论 |
| **不识别结构化表格** | 表格内条款可能漏抽 |
| **扫描件/图片** | 不支持 OCR，需先转文字 |
| **法条提示可能过时** | 脚本内置的是编写时的法条，**必须实时核验** |
| **只处理中文** | 英文/中英混排条款可能漏抽 |

> 📌 **正因为有这些局限，脚本输出只能作为"提示 HR 重点检查这些地方"的辅助**，
> **不能替代逐条阅读原文，更不能替代法条核验。**

### 2.5 CLI 契约

| 情形 | 退出码 | 输出 |
|---|---|---|
| 正常命中 | 0 | 人读格式 / `--json` 输出 `status="ok"` |
| 未命中已知类型 | 0 | 人读格式提示 / `--json` 输出 `status="no_match"`、`clauses=[]` |
| 文件不存在 | 1 | stderr 提示 + 降级建议；`--json` 输出 `status="error"`、`error.code=FILE_NOT_FOUND` |
| 文档损坏 / 无法解析 | 1 | 同上，`error.code=DOCUMENT_READ_FAILED`，**无裸堆栈** |
| `--type` 未指定任何有效类型 | 2 | 列出可选类型 |
| `--type` 含未知类型 | 2 | 列出可选类型 |
| `--min-risk` 非法取值 | 2 | argparse 处理 |

`--json` 输出结构固定：`meta` / `status` / `clauses` / `error` / `disclaimer`，
**无论是否命中都是合法 JSON 对象**，便于宿主稳定消费。

## 三、`knowledge_sync_check.py` 用法

### 3.1 命令示例

```bash
# 基本体检
python scripts/knowledge_sync_check.py

# 收紧时效阈值（默认 180 天）
python scripts/knowledge_sync_check.py --days 90

# 同时输出 Markdown 报告
python scripts/knowledge_sync_check.py --report ./sync-report.md

# JSON 输出（便于定时任务）
python scripts/knowledge_sync_check.py --json
```

### 3.2 检查项

| 代码 | 级别 | 含义 |
|---|---|---|
| `META-INCOMPLETE` | 阻塞 | 缺必填字段（layer/last-checked/confidence） |
| `NO-STALENESS-TRIGGER` | 阻塞 | E1 文件未登记失效触发条件 |
| `DRAFT-CONFIDENCE` | 阻塞 | confidence=draft，尚未系统核验 |
| `DATE-UNPARSEABLE` | 阻塞 | last-checked 日期无法解析，核验时效不可判定 |
| `DATE-IN-FUTURE` | 阻塞 | last-checked 为未来日期 |
| `CONFIDENCE-INVALID` | 阻塞 | confidence 取值不在 high/medium/draft 内 |
| `LAYER-INVALID` | 阻塞 | layer 取值非法（含自称 A1 的自证循环风险） |
| `EMPTY-REFERENCES` | 阻塞 | references 目录下无任何 .md 文件 |
| `STALE` | 警告 | 距上次核验超过阈值 |
| `META-MISSING` | 警告 | 非白名单文件但无元数据 |
| `MEDIUM-CONFIDENCE` | 警告 | 含未完全核验内容 |
| `READ-ERROR` | 警告 | 文件无法读取（编码/权限） |
| `NO-FRONTMATTER` | — | 方法层文件，设计如此，不报 |
| `AGING` | 提示 | 接近时效阈值 |

**退出码**：`0` 无阻塞｜`1` 有阻塞｜`2` 参数错误 → 可直接接入定时任务。

> ⚠️ 阻塞项只针对**元数据**，不代表知识层内容有误；同样，退出码 0 也不代表内容正确。

### 3.3 建议频率

| 场景 | 建议 |
|---|---|
| 更新解聘手册/SOP 后 | 立即运行 |
| 检索中发现知识层与法条不符后 | 立即运行 |
| 常规体检 | 每季度运行一次 |
| 自动化 | 配 `--json` 接入定时任务，退出码非0时告警 |

## 四、`generate_docx.py` 用法

```bash
# 转换报告为 Word
python scripts/generate_docx.py "./compliance-assessment/<事项>-<日期>/用工合规评估报告.md"

# 指定输出路径
python scripts/generate_docx.py 报告.md -o ./输出/报告.docx

# 允许覆盖已存在的目标文件（默认拒绝，避免误覆盖既有交付物）
python scripts/generate_docx.py 报告.md -o ./输出/报告.docx --overwrite
```

### 4.1 行为保证

| 保证 | 说明 |
|---|---|
| **实质文本不丢** | 转换后做**内容核对**：正文中每条实质文本都必须能在 docx 中找到，否则**中止生成、不写文件**，并列出缺失项 |
| **未闭合代码围栏不丢** | 遇到未闭合的 ``` 围栏，**保留其内容**写入 Word 并输出告警，不静默丢弃 |
| **来源不丢** | 正文角标 URL（`["https://..."]`）**转写为文末尾注条目**，正文留"来源见尾注"占位；核对不通过即失败 |
| **空报告拒绝** | 空 Markdown 或无实质内容的 Markdown **直接拒绝**，不生成空 Word |
| **源件保护** | 输出路径与输入为同一文件（含大小写差异、硬链接）时**拒绝**；输出后缀非 `.docx` 时拒绝 |
| **覆盖策略明示** | 目标文件已存在时**默认拒绝**，需显式 `--overwrite` |
| **缺依赖受控降级** | 缺 `python-docx` 时以**退出码 1** 明确声明并给出降级建议，**无裸堆栈** |

**注意**：
- 脚本路径**不要写死**，先定位到 `SKILL.md` 所在目录再调用其下的 `scripts/`；
- 若 `python-docx` 不可用，**说明具体原因**并降级为仅 Markdown，**不得静默失败**。

## 五、降级规则（硬性）

```
脚本不可用 / 报错 / 未安装
        ↓
① 明确告知用户"该能力不可用"及原因
        ↓
② 改用降级路径：
   · 抽取 → 直接阅读原文，人工识别关键条款
   · 体检 → 人工核对各文件 frontmatter
   · 转换 → 仅交付 Markdown
        ↓
③ 在报告中说明"本次未使用脚本能力，结论基于人工阅读"
        ↓
④ ❌ 不得因此跳过检索、核验或闸门
```

> 🔴 **脚本能力缺失不是降低标准的理由。**
> 知识层防错、两道闸门、A1 核验，全部是**流程纪律**，与是否有脚本无关。

## 六、扩展脚本的原则

若将来增加脚本：

1. **纯标准库优先**，非必要不引入依赖；
2. 脚本输出**永远是线索**，不是结论；
3. 脚本内置的法条提示**必须标注"需实时核验"**；
4. 失败必须**显式报错**，不静默返回空结果；
5. 新脚本在本文档登记，说明用途、依赖、降级路径。
