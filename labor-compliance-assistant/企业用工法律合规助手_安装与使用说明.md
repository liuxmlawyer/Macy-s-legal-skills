## 一、是什么

**企业用工法律合规助手** 是一个面向企业 HR 和老板的 AI Skill（技能包），用于对**用工管理全流程**做法律合规评估。

它把一句普通的用工需求（如"我想解除一个绩效不好的员工"）自动转化为：

> 理解预判 → 关键澄清 → 解除路径 → 证据清单 → 风险定级 → 结构化评估报告 + 可执行建议

v3.0 系列的三个核心价值：

| 价值 | 说明 |
|---|---|
| **咨询不草率** | 两道硬闸门，不该问的不问清楚不出报告；**已授权的不重复问** |
| **结论不自欺** | 知识层防错机制，禁止用自己写的总结论证自己 |
| **知识可维护** | 知识层元数据体检，字段、日期、枚举、时效、交叉引用一次查清 |

## 二、v3.0.1 相比 v3.0 改了什么

### 2.1 修正与 v3.0 的差异

| 类别 | 变更 |
|---|---|
| **法律表述修正** | 试用期提示与现行《劳动合同法》第19条对齐（无固定期限合同**可以**约定试用期，上限 6 个月）；竞业限制补偿区分**在职 / 离职后**；终止补偿按第46条逐情形判断（提出方、终止原因、续订条件），不再以"终止一律 N"概括 |
| **程序表述收窄** | 第43条"未设工会通知全体职工"不再作为通用法定替代程序；地域适用不再使用固定排序，改为按争议类型与具体规范分别判断 |
| **脚本行为加固** | Word 转换增加**内容与来源核对**（缺失即失败，不写文件）；未闭合代码围栏**保留内容**；正文角标来源**转尾注**而非剥除；空报告**拒绝**生成；输出与输入同文件**拒绝**；缺依赖**明确声明**并以退出码 1 返回 |
| **抽取器修正** | 试用期与合同期限**联合判断**；同一句多个独立义务**全部保留**（不再只归入首个命中类型）；类型关键词约束（"竞业限制期限为五年"不再被归入试用期）；合同期限未识别时输出**待核验**提示，不暗示无风险 |
| **能力承诺收窄** | 同步检测脚本明确降为**元数据体检**，删除"法律一变即提示失效"等无实现承诺；补空目录、日期合法性、枚举取值校验 |
| **检索纪律统一** | 取源顺序在各处统一为"权威性排序 + 能力探测"两条线；删除开发者本机环境事实；官方直取与 MCP 取得的原文具有同等权威性，不得因未接 MCP 就降格为"仅知识库" |
| **交互授权继承** | 已作出的路线、形式、范围授权在同一任务内完整继承；**按任务路由加载模块**，非解除类咨询不被套入解聘流程 |
| **质量清单分档** | 区分硬法律校验 / 任务适用性 / 交付偏好；允许有依据地标"不适用"，且**禁止为通过清单而伪造数据** |

### 2.2 实体内容层

`dismissal-pathway.md`、`evidence-checklist.md`、`kb-search-protocol.md` 等核心文件**实体内容有实质修正**，
本轮新增 `references/script-clause-registry.md`（脚本固化法律提示登记册），
使**写在代码里的法条提示**进入知识层可追踪、可维护的范围。

## 三、安装说明

### 3.1 环境要求

- 本包是文档型候选技能。已做本地结构与脚本校验；各宿主原生安装、自动触发、重启识别须单独验收（本包已按「描述场景即自动触发」配置，具体见 3.5）。WorkBuddy历史rc1测试摘要不代表rc2已通过；Claude、Coze、Dify等平台未验证，不承诺通用原生安装。
- **核心能力无依赖**：纯文档型技能，复制即可用
- **可选增强**：Python 3 环境可运行 `scripts/` 下脚本；无 Python 不影响使用

### 3.2 安装步骤

```
1. 解压 labor-compliance-assistant_v3.0.1-rc3.zip
   （包内顶层目录为 labor-compliance-assistant/）

2. 将解压得到的 labor-compliance-assistant 文件夹整体放入你的 Skill 目录
   （如 E:\SKILL安装\自建skill\ 或平台的技能目录）

3. 确认目录结构：
   labor-compliance-assistant\
   ├── SKILL.md                    ← 主入口
   ├── RELEASE-MANIFEST.md
   ├── references\                 ← 21 个参考文件
   ├── assets\
   │   └── working-file.md         ← 工作底稿模板
   ├── scripts\                    ← 3 个脚本（可选增强）
   │   ├── knowledge_sync_check.py
   │   ├── extract_labor_terms.py
   │   └── generate_docx.py
   └── user-knowledge\             ← 企业政策包（可选）
       ├── README.md
       ├── assets\manifest-template.md
       ├── policies\
       ├── risk-appetite\
       ├── procedures\
       └── routing\

4. 重启/刷新环境，确认技能被识别
   （本技能默认「描述场景即自动触发」；也可随时用 `/labor-compliance-assistant` 显式调用。
    详见 [3.5 技能触发方式](#35-技能触发方式)）
```

> 📌 `user-knowledge/` 下的四个子目录在包内为**空目录占位**（`.keep` 文件），
> 用途是让使用者按目录结构放入企业材料；`.keep` 本身无内容，可删除。

### 3.3 可选：安装脚本依赖

```bash
pip install python-docx      # 仅 .docx 读取与 Word 生成需要
```

**不装也能用**——脚本能力降级，主流程不受影响。
缺依赖时脚本会**以退出码 1 明确声明**并给出降级建议，**不会静默失败或抛裸堆栈**。

### 3.4 卸载与移除

1. 删除技能目录（`labor-compliance-assistant/`）即可移除技能本体；
2. 如曾使用过脚本，可在工作目录删除生成的 `sync-report.md`、`*.docx` 与 `__pycache__/`；
3. `user-knowledge/` 中的企业材料如需保留，请**先移出**再删目录；
4. 卸载**不会**修改任何已交付给客户或第三方的报告文件。

### 3.5 技能触发方式

本技能**默认即为「描述场景即自动触发」**：安装后直接用日常语言描述用工场景，宿主即会自动匹配并进入本技能。

- **自动触发的依据**：`SKILL.md` 的 `description` 字段已写明适用场景枚举与意图（招聘录用、劳动合同、试用期、绩效考核、调岗降薪、工时休假、薪酬社保、三期医疗工伤、解除终止、竞业保密、制度效力、用工形态等），宿主据此自动匹配。
- **也可手动调用**：随时输入 `/labor-compliance-assistant` 显式调用，适合在描述里需要点名指定本技能的场景。
- **触发面较宽是设计使然**：本技能针对 HR/老板的用工合规评估，描述场景即进入完整评估流程（含多轮澄清）。若希望改为「仅手动调用」，需在宿主技能设置中将本技能切换为仅手动。

> 📌 **触发方式属于接收方本机设置，不随包分发**。本包内容对「自动触发」与「仅手动」两种模式完全一致；接收方无论采用哪种模式，技能能力、实体内容与输出格式均无差异。

## 四、快速上手

直接说你的用工需求即可，例如：
- "我想解除一个绩效不好的员工，怎么做？"
- "三期员工可以调岗吗？"
- "员工拒绝培训和调岗怎么办？"
- "竞业限制协议怎么签才有效？"
- "法定节假日加班可以只补休吗？"

系统会：
1. **出理解纪要 + 预判**（解除/终止类任务才做红黄绿预判），并等你选路线；
2. **追问关键信息**（工龄、工资、证据、特殊情形、所在城市，一轮 1–4 问）；
3. **双通道检索**（政策包 + 权威法条原文交叉核验）；
4. **确认交付形式**（md+docx / 仅 md / 仅对话内）；
5. **输出评估报告**。

## 五、两道咨询闸门

### 闸门一 · 路线闸门

**适用条件**：任务是**解除/终止类**，且用户首条消息只描述场景、**未明确授权直出**。

```
已理解：<场景复述>
初步预判：🟡 黄灯 —— 有书面考核但无培训/调岗记录，直接解除有违法风险

请选择下一步怎么推进：
A. 直接生成报告
B. 先补充关键事实再评估
C. 只出解除路径与证据清单
D. 审阅已有材料并标注风险
E. 暂停在业务理解纪要
```

**红黄绿预判的含义**：

| 灯色 | 含义 |
|---|---|
| 🔴 红灯 | 属第42条不得解除情形，或缺制度效力/客观证据 → **不得启动第40、41条解除路径**（第42条**不限制**第36条协商解除与第39条过错解除） |
| 🟡 黄灯 | 要件基本齐备但有缺口 → 先补证据、补程序 |
| 🟢 绿灯 | 要件齐备、证据充分、程序清晰 → 走对应路径 |

> 💡 预判只是**初步方向**，最终结论仍以检索核验后的分析为准。
> ⚠️ 闸门一**不适用于**工资、休假、社保、录用条件等非解除类咨询——这类咨询不会被套入解聘流程。

### 闸门二 · 生成形式闸门

出报告前确认形式，**不会由系统默认决定**：

```
A. 本地 Markdown + Word（.docx）—— 适合归档和正式交付
B. 仅本地 Markdown —— 适合后续自行编辑
C. 仅在对话内输出 —— 适合快速查看
D. 其他 —— 写入指定文档系统（需已授权连接器）
```

> **可跳过条件**：你已明确指定形式；或你在本次对话中已完成过一次形式选择；
> 或你已授权"直接出报告、不用再问"。
> ⚠️ 已作出的授权**在同一任务内完整继承**，不会就同一件事反复确认。

## 六、知识层防错机制

### 6.1 问题在哪

这个技能里写着"不能胜任解除要三步法""第42条有六项情形"——
这些都是**基于经验与学习材料的人工总结**，**不是法条原文**。

它们可能：条号记错、要件概括偏差、口径过时、地区差异遗漏。

**更危险的是**：如果直接引用这些总结当作依据，就等于
**用自己写的总结证明自己写的东西对** —— 这叫自证循环。

### 6.2 三层信任分级

| 层级 | 是什么 | 能否支撑确定性结论 |
|---|---|---|
| **A1** | 权威源法条原文（国家法律法规数据库 / 专业法律数据库 / 官方站点直取） | ✅ **可以** |
| **E1** | 技能自带经验总结（解除路径、证据清单） | ❌ **不可以** |
| **E2** | 企业知识库（`user-knowledge/` 政策包） | ❌ **不可以** |

> 📌 **来源可信度与工具可用性是两个独立维度**：
> 没接法律 MCP 只是**取得路径**变了，通过官方站点直取到的原文**权威性不变**；
> 但确实没取到原文的，如实标"未核验"——**绝不编造**工具调用。

### 6.3 具体规则

**报告依据栏只能这样写**：
```
✅ 《劳动合同法》第40条第2项（2012年修正，现行有效）
✅ 《劳动争议司法解释（二）》（法释〔2025〕12号，2025-09-01施行）
```

**绝对不能这样写**：
```
❌ 技能手册V4 规定不能胜任解除需三步法
❌ 解聘手册的判断标准是……
❌ 本技能认为……
```

**E1 知识层的正确用法**：
- 🔍 **检索线索** —— 提示"该去查第40条了"
- 🧠 **分析框架** —— 组织问题的顺序
- ⚠️ **风险提示** —— 告诉你"这里最容易踩坑"
- ✍️ **证据清单模板** —— 帮 HR 自查

### 6.4 发现错误时怎么办

```
检索发现知识层与法条不一致
    ↓
① 立即停止使用该条知识层内容
    ↓
② 以法条原文为准出具结论
    ↓
③ 差异写入报告「待确认」区
    ↓
④ 提示你：建议更新知识层该处，附具体改法
    ↓
⑤ 你确认后修订 → 更新核验日期与置信度
```

### 6.5 每份报告都会披露

```
### 知识层核验状态
- 引用文件：dismissal-pathway.md（confidence: high，核验于 2026-10-14）
- 已回权威源核验的法条：第36/39/40/41/42/43条等
- 发现的差异：1 处（见上）
- 未核验项：地区口径需按用工所在地实时检索
- 结论可靠性：确定性结论均建立在 A1 权威源之上
```

## 七、知识层元数据体检

### 7.1 运行方式

```bash
cd labor-compliance-assistant/scripts
python knowledge_sync_check.py --days 180 --report ./sync-report.md
```

### 7.2 检测什么

| 级别 | 含义 |
|---|---|
| 🔴 阻塞 | 缺必填元数据 / 未登记失效触发 / 置信度为 draft / **日期非法或为未来日期 / 枚举取值非法 / 目录为空** |
| 🟡 警告 | 距上次核验超过阈值（默认180天）/ 含未完全核验内容 / 文件无法读取 |
| ⚪ 提示 | 接近时效阈值 |

**退出码**：`0` 无阻塞 ｜ `1` 有阻塞 ｜ `2` 参数错误 → 可接入定时任务自动告警。

### 7.3 ⚠️ 它不能做什么（重要）

| 它**不能**做 |
|---|
| ❌ 联网抓取法规、**发现法律是否已修订** |
| ❌ 比对知识层表述与现行法条正文是否一致 |
| ❌ 判断某条法律解释是否已被推翻 |
| ❌ 自动更新知识层内容 |

> 🔴 **「体检通过」只表示元数据自洽，不表示内容正确或法律有效。**
> 法律变化只能在检索阶段回权威源核验时发现。本脚本是**元数据体检工具，不是法律变更监控服务**。

### 7.4 什么时候该跑

| 场景 | 建议 |
|---|---|
| 你更新了解聘手册 / SOP | 立即运行 |
| 报告里出现了"知识层待更新提示" | 按提示修订后运行 |
| 常规体检 | 每季度 |
| 自动化 | 配 `--json` 接入定时任务 |

### 7.5 元数据长什么样

`references/dismissal-pathway.md` 文件开头：

```yaml
---
layer: E1                                    # 信任层级
basis: 《劳动用工—员工解聘手册（增强修订版 V4）》
basis-version: V4 / 2026-09
verified-against:                             # 已回 A1 核验的法条
  - 《劳动合同法》第39条（过错解除6项）
  - 《劳动合同法》第40条（无过错解除3项）
last-checked: 2026-10-14
confidence: high
staleness-trigger:                           # 什么情况下失效
  - statute-amended
  - judicial-interpretation-updated
  - regional-guideline-updated
owner: Macy
---
```

> 📌 **你更新知识层内容后，记得同步更新 `last-checked` 和 `confidence`。**
> ⚠️ 本地文件的 `layer` 只能是 `E1` 或 `E2`——**不得自称 A1**（那会形成自证循环）。

## 九、输出内容

一份完整的用工法律合规评估报告，通常包含：

- **评估结论摘要**（总体判断 / 主要风险 / 核心建议）
- **用工背景与评估范围**
- **法律分析**（按"主体关系：核心风险"组织）
- **待专业人员确认事项**
- **整改建议**（针对哪项风险·谁·何时·做什么·降险效果）
- **风险与建议汇总表**
- **证据清单**（可选）
- **合规处理流程**（可选，对接既有 SOP）
- **知识层核验状态**（必填）
- **免责声明 + 来源尾注**

## 十、接入企业知识库（政策包）

### 10.1 快速接入

1. 复制模板：`user-knowledge/assets/manifest-template.md` → `user-knowledge/manifest.md`
2. 填入企业信息、文件清单、**民主程序与公示记录**
3. 把制度文件放进对应目录：

```
user-knowledge/
├── manifest.md              ← 必填，说明书
├── policies/                ← 员工手册、绩效制度、奖惩制度
├── risk-appetite/           ← 风险偏好
├── procedures/              ← SOP、通知书模板
└── routing/                 ← 审批权限表
```

### 10.2 重点提醒

> 🔴 **企业制度未经民主程序或未公示，可能整体不能作为解除依据。**
> 这是仲裁败诉最常见的原因之一，务必在 manifest 中如实记录。

### 10.3 使用原则

- 政策包**仅在你明确授权后加载**；
- 政策**可以抬高内控等级**（要求更严），**不能降低法定风险**（放宽程序）；
- 政策与法律冲突时**以法律为准**，技能会提示你修订；
- **跨客户不复用**政策内容。

## 十一、使用示例

**用户问**："我想辞掉一个绩效不好的员工，怎么做？"

**第一轮回复（闸门一）**：

> **已理解**：某员工绩效考核不达标，公司考虑解除劳动合同。员工入职约2年，月薪约1.2万，公司在杭州。
>
> **初步预判**：🟡 **黄灯**
> - 有利因素：若考核制度经民主程序且已公示，第40条路径可行
> - 风险点：**未见培训或调岗记录**，直接解除极可能构成违法解除
> - 当前最大变量：**证据**——制度效力证据 + 考核原始记录
>
> 请选择下一步怎么推进：
> A. 直接生成报告　B. 先补充关键事实再评估　C. 只出解除路径与证据清单
> D. 审阅已有材料并标注风险　E. 暂停在业务理解纪要

**用户选 B 后，系统追问（1轮4问）**：

1. 员工入职多久？合同类型与期限？
2. 是否有**书面**绩效考核制度？是否经职工代表大会讨论并公示？
3. 有无培训记录、调岗记录或绩效改进计划（PIP）？
4. 员工是否处于三期、医疗期、工伤或距退休不足5年？

**用户答完后，系统检索核验并出报告**（闸门二确认形式后）。

## 十二、风险与边界说明

- 本技能为**辅助研究工具**，不替代具备劳动法律资格的律师/法务的正式意见；
- 涉及**违法解除、三期解除、克扣工资、未缴社保**等高风险定性，系统会强制升级为人工确认；
- **知识层（E1）不是法律依据**——所有确定性结论必须回权威源取法条原文；
- 脚本输出的是**风险线索**，不是法律结论，且**存在漏抽与误报**（表格、扫描件、复杂句式尤甚）；
- 结论基于指定日期、用工所在地、现有材料生成；劳动法规与地区口径可能变化；
- 请勿把"待专业人员确认"事项当作确定性放行依据直接执行。

## 十四、常见问题

**Q1：必须配置企业知识库才能用吗？**
不是。政策包是可选增强，未配置时自动用权威公开法规做评估。

**Q2：结论一定准确吗？**
不能承诺绝对准确。系统通过 **A1 权威源核验 + 来源分级 + 时效核验 + 限定保留 + 三道防错闸门** 大幅降低错误风险。但知识层（E1）本身是经验总结，可能有误——所以规定它**不能作为依据**，必须回法条原文核验。涉及专业判断与地区口径的，一律标"需专业人员确认"。

**Q3：技能里的"三步法"准不准？**
它是**经验总结**，作为检索线索和分析框架使用。报告依据栏只会写法条名称和条号，不会写"技能手册说"。如果核验中发现总结与法条不一致，系统会**主动提示你更新**。

**Q4：我更新了解聘手册，需要做什么？**
1. 更新对应知识层文件内容
2. 同步更新文件开头的 `last-checked` 与 `confidence`
3. 运行 `python scripts/knowledge_sync_check.py --report ./sync-report.md`
4. 按报告中的待办确认无遗漏

> ⚠️ 第 3 步是**元数据体检**，它能查出"你没更新日期/置信度"，但查不出"法律变了"。

**Q5：没有 Python 环境能用吗？**
能用。脚本全是**可选增强**，核心能力是纯文档。没有 Python 时，脚本能力自动降级（改为人工读原文、人工核对元数据、仅交付 Markdown），主流程完全不受影响。

**Q6：地区差异怎么处理？**
**不存在**"实际用工所在地 ＞ 履行地 ＞ 签订地 ＞ 注册地"这样的通用排序。
实体标准按《劳动合同法实施条例》第14条判断（含"注册地标准更高且已约定则从其约定"的例外），
程序管辖按《劳动争议调解仲裁法》第21条等单独判断，**两者不是同一问题**。
系统提供检索词模板与高频争点清单，但**地区口径每次都要实时检索**，知识层里的地区表只是提示框架，不能照用。

**Q7：员工信息安全吗？**
按 `data-handling.md` 执行：员工姓名用代号、身份证/手机号不出现在报告中、薪酬只给区间、病历孕产只写"是否存在"。政策包仅授权加载、跨客户不复用。

**Q8：为什么第一轮不直接给答案？**
因为用工决策的结论高度依赖几个关键事实（工龄、是否有培训记录、是否三期、所在城市）。
不知道这些就直接出报告，容易给出**看起来专业但用不了**的结论。两道闸门是为了把关键事实问清楚。

**Q9：脚本说"未抽取到风险线索"，是不是就没风险了？**
不是。抽取器是**正则启发式**，表格、扫描件、图片、复杂句式都可能漏抽。
输出中会明确提示"未命中不等于无风险"，仍须回原文逐条阅读。

**Q10：Word 转换失败了怎么办？**
脚本会说明具体原因并给降级建议（改为仅交付 Markdown），**不会静默生成空文档或吞掉正文**。
若报告有来源角标，脚本会把它们转成文末尾注；若转换后内容核对不通过，脚本**中止生成**并列出缺失项，
不会产出一份内容不完整的 Word。
