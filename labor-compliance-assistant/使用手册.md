## 一、五分钟上手

### 1.1 直接说人话

不需要说法条编号，用日常语言描述就行：

```
"我想辞掉一个绩效不好的员工，怎么做？"
"三期员工可以调岗吗？"
"员工拒绝培训和调岗怎么办？"
"竞业限制协议怎么签才有效？"
```

### 1.2 它会怎么回应你

**第一轮不会直接给答案**，而是：

```
已理解：<把你的场景复述一遍>
初步预判：🟡 黄灯 —— <一句话理由>

请选择下一步怎么推进：
A. 直接生成报告
B. 先补充关键事实再评估
C. 只出解除路径与证据清单
D. 审阅已有材料并标注风险
E. 暂停在业务理解纪要
```

**为什么这样**：用工结论高度依赖四五个关键事实（工龄、有没有培训记录、是不是三期、在哪个城市）。不知道这些就出报告，容易给出**看着专业但用不了**的东西。

### 1.3 你可以随时喊停

| 你说 | 它会 |
|---|---|
| "直接出报告，不用问" | 跳过闸门一，但**不会跳过法条核验** |
| "只给我解除路径和证据清单" | 走C选项，不出完整报告 |
| "出个 Word" | 跳过闸门二，直接出 md+docx |
| "只要 Markdown" | 跳过闸门二，只出 md |
| "先看看我这份制度" | 走D选项，逐条标注风险 |

## 二、它是怎么工作的

### 2.1 六个阶段

```
A. 理解场景 + 红黄绿预判  → 🚦闸门一：你选路线
B. 追问关键事实（一轮1-4问）
C. 梳理法律问题
D. 检索核验（知识库 + 权威法条双通道）
E. 风险定级 + 出报告        → 🚦闸门二：你选格式
F. 你提意见 → 逐条改 → 定稿
```

### 2.2 双通道检索（这是它跟普通问答的区别）

```
① 你的内部材料（如果授权接入）
      ↓ 命中且可核 → 作为「内部口径」
② 权威法条原文（国家法律法规数据库 / 北大法宝）
      ↓ 两者不一致 → 以法条为准，差异写进报告
```

**即使你的内部材料已经给了结论，它也会去查法条原文。**

理由：劳动法规逐年变动，模型的记忆不可靠。**跳过检索 = 承诺准确但无法保证。**

### 2.3 它不会做的事

| 不做 | 原因 |
|---|---|
| 跳过检索直接给结论 | 会引用到已废止的条文 |
| 编造条文号或案例号 | 找不到就说找不到 |
| 拿内部手册当法律依据 | 手册是你写的总结，不是法律 |
| 承诺"零风险""一定合法" | 劳动法高度依赖个案事实 |
| 替你做最终决定 | 高风险定性必须人工确认 |

## 三、两道闸门

### 闸门一 · 路线闸门

**作用**：防止一句话没说清就出报告。

**你必须做的**：从A-E里选一条。

**可以跳过的情形**：你明确说"直接生成报告""不用追问""按现有材料出"。

**即使跳过，也不能省**：
- ❌ 不能跳过法条检索
- ❌ 不能跳过知识层校验
- ❌ 不能跳过"待确认事项"的披露

### 闸门二 · 形式闸门

**作用**：交付形式由你决定，不由它默认。

| 选项 | 何时选 |
|---|---|
| A. md + docx | 要归档、要发给老板或法务 |
| B. 仅 md | 你要自己再编辑 |
| C. 仅对话内 | 快速看一眼 |
| D. 其他 | 你有文档系统（需已授权） |

**可以跳过的情形**：你已明确指定形式。

**如果选了A但Word没生成**，它会明确告诉你原因（通常是缺 `python-docx`），不会假装成功。

## 四、红黄绿怎么看

红黄绿来自技能的「解除路径」经验层，是**初步方向**，不是最终结论。

| 灯色 | 含义 | 你该做什么 |
|---|---|---|
| 🔴 **红灯** | 属于法定不得解除情形，或缺"制度效力"/"客观证据" | **先别启动第40/41条路径**；第36条协商、第39条过错解除及法定终止分别核验条件，不把第42条外推为全面禁止解除 |
| 🟡 **黄灯** | 要件基本齐备但有缺口 | 补证据、补程序，**先不要发解除通知** |
| 🟢 **绿灯** | 要件齐备、证据充分、程序清晰 | 走对应路径执行 |

### 红灯的几种典型情形

- 员工在**孕期/产期/哺乳期**（但注意：只限制第40、41条）
- 员工在**医疗期内**
- 员工**患职业病或因工负伤**丧失劳动能力
- 员工**连续工作满15年且距退休不足5年**
- 从业岗位属**职业病危害作业**，解除前未做离岗前健康检查
- **完全没证据**——只有"老板觉得他不行"

> ⚠️ 红灯不等于"绝对不能辞"。三期女职工如果有严重违纪，仍可走第39条过错解除。
> **协商解除（第36条）更是不受第42条限制**——这是三期员工最常用的安全通道。

### 灯色会不会变

**会。** 灯色是初判，取决于你补充的事实：

```
初判黄灯（因为"没看到培训记录"）
   ↓ 你补充："其实3个月前做过培训，有签到表"
绿灯（因为培训记录存在，程序完整）
```

## 五、知识层防错：为什么报告里不写"手册说"

### 5.1 问题的本质

这个技能里写着"不能胜任解除要三步法""第42条有六项情形"。

这些是**基于经验与学习材料的人工总结**，**不是法条原文**。它们可能：
- 条号记错了
- 要件概括有偏差（比如法条是"培训**或者**调岗"，总结写成"两者都要做"）
- 口径过时了
- 地区差异漏了

**最危险的地方**：如果直接拿这些总结当依据，就等于
**用自己写的总结证明自己写的东西对** —— 这叫自证循环。

### 5.2 三层信任分级

| 层级 | 是什么 | 能否作结论依据 |
|---|---|---|
| **A1** | 权威源法条原文 | ✅ 可以 |
| **E1** | 技能自带经验总结 | ❌ 不可以 |
| **E2** | 你的企业知识库 | ❌ 不可以 |

### 5.3 你会看到的正确写法

报告依据栏长这样：

```
✅ 依据：《劳动合同法》第40条第2项（2012年修正，现行有效）
✅ 依据：《劳动争议司法解释（二）》（法释〔2025〕12号，2025-09-01施行）
```

而不是：

```
❌ 依据：技能手册V4 规定不能胜任解除需三步法
❌ 依据：解聘手册的判断标准是……
```

### 5.4 每份报告都有「知识层核验状态」

```
### 知识层核验状态
- 引用文件：dismissal-pathway.md（置信度 high，核验于 2026-10-14）
- 已回权威源核验的法条：第36/39/40/41/42/43条等 10 项
- 发现的差异：1 处（见下）
- 未核验项：地区口径需按用工所在地实时检索
- 结论可靠性：本次确定性结论均建立在法条原文之上

#### 发现的差异
| 位置 | 知识层表述 | 法条实际表述 | 处置 |
|---|---|---|---|
| §5.4 | 三步法：培训→复考→解除 | 第40条第2项：「经培训**或者**调整工作岗位」 | 以法条为准；建议修订 |
```

**没有差异时也会写"本次未发现差异"**，不会省略这一节。

### 5.5 看到"知识层待更新提示"时怎么办

这不是错误，是**它在提醒你内容需要修订**。

```
⚠️ 知识层待更新提示

核验中发现 dismissal-pathway.md §5.4 的表述与现行《劳动合同法》
第40条第2项存在差异：
- 知识层表述：三步法（培训 → 复考 → 解除）
- 法条原文：经培训或者调整工作岗位，仍不能胜任的

本次分析已以法条原文为准，不影响结论。
建议您更新知识层该节，具体改法见下方建议。
```

**你要做的**：
1. 看懂它说的差异是什么
2. 判断采纳与否（你也可以不改，但差异会持续提示）
3. 采纳 → 让它帮你改 → 改完更新核验日期

> ⚠️ **不披露比错误本身更危险。** 所以即使差异不影响当前结论，它也会告诉你。

## 六、你更新了知识层怎么办

### 6.1 什么时候需要更新

| 情况 | 动作 |
|---|---|
| 你换了新版解聘手册 | 更新对应知识层文件 |
| 报告出现"待更新提示" | 按提示改 |
| 检索时发现法条变了 | 更新相关条目 |
| 定期体检（建议每季度） | 跑一次检测脚本 |

### 6.2 三步走

**第一步：改内容**

打开 `references/dismissal-pathway.md`（或对应的知识层文件），改你要改的部分。

**第二步：改元数据**

文件开头的这段要同步更新：

```yaml
---
layer: E1
basis: 《劳动用工—员工解聘手册（增强修订版 V4）》
basis-version: V4 / 2026-09          ← 改成新的依据版本
verified-against:                     ← 重新核验的法条清单
  - 《劳动合同法》第40条
  - ...
last-checked: 2026-10-14            ← 改成今天
confidence: high                     ← 按实际核验程度填
staleness-trigger:                   ← 保持不变
  - statute-amended
  - ...
owner: Macy
---
```

**三个字段的含义**：

| 字段 | 怎么填 |
|---|---|
| `last-checked` | **你这次实际核验的日期** |
| `confidence` | `high` = 逐条核验过 ｜ `medium` = 部分核验 ｜ `draft` = 还没系统核验 |
| `basis-version` | 你依据的新手册版本号 |

**第三步：跑检测**

```bash
cd labor-compliance-assistant/scripts
python knowledge_sync_check.py --report ./sync-report.md
```

输出会告诉你：
- 哪些文件过期了
- 哪些缺元数据
- 两份知识层之间有没有互相矛盾

### 6.3 检测项速查

| 标记 | 含义 | 该做什么 |
|---|---|---|
| 🔴 阻塞 | 缺必填元数据 / 未登记失效触发 / 置信度是 draft | **先补齐再用** |
| 🟡 警告 | 距上次核验超过180天 / 含未完全核验内容 | 安排重新核验 |
| ⚪ 提示 | 快到时效阈值了 | 纳入下季度计划 |

退出码：`0` = 干净，`1` = 有阻塞项。可以接定时任务自动告警。

### 6.4 改完记得检查交叉引用

知识层文件之间会互相引用，改一处要看看会不会造成矛盾：

| 你改了 | 也要看看 |
|---|---|
| 第42条六项情形 | `dismissal-pathway.md` §零、`evidence-checklist.md` §四、`risk-grading.md` |
| 经济补偿3倍封顶 | `dismissal-pathway.md` §三、`kb-search-protocol.md` §五、`evidence-checklist.md` §5.1 |
| 不能胜任三步法 | `dismissal-pathway.md` §5.4、`evidence-checklist.md` §二/§三 |

检测脚本会自动提示漏掉的交叉引用。

## 七、接入你的企业制度

### 7.1 值得接入吗

**值得**，如果你有以下情况：
- 有成文的员工手册/规章制度
- 有内部的解除流程SOP
- 有审批权限规定
- 处理过类似案件，有既定口径

**不接也能用**，系统会用公开法条做评估。

### 7.2 怎么接

**第一步：复制模板**

把 `user-knowledge/assets/manifest-template.md` 复制为 `user-knowledge/manifest.md`。

**第二步：填信息**

最重要的是这两块：

```
## 文件清单
（列你的制度文件、版本、生效日期）

## 民主程序与公示记录   ← 最关键！
| 制度名称 | 职工代表大会决议 | 协商日期 | 公示方式 | 公示日期 | 签收证据 |
| 员工手册v3.2 | 2026-02-20第3届2次 | 2026-02-18 | 签收表 | 2026-03-01 | 原件在HR部 |
```

**第三步：放文件**

```
user-knowledge/
├── manifest.md              ← 必填
├── policies/                ← 员工手册、绩效制度、奖惩制度
├── risk-appetite/           ← 风险偏好
├── procedures/              ← SOP、通知书模板
└── routing/                 ← 审批权限表
```

**第四步：使用时授权**

跟它说"可以参考我们的员工手册和绩效制度"。

### 7.3 一个必须提醒的事

> 🔴 **制度没公示过 = 仲裁时大概率败诉。**

很多企业制度写得很好，但**从来没让员工签收过**。
仲裁时企业拿不出"员工已知悉"的证据，制度就不能作为解除依据。

**这不是法律风险，是证据风险。** 所以 manifest 里那张公示记录表，请如实填——
填不出来本身就是重要发现。

### 7.4 政策与法律冲突时

```
法律要求 > 企业政策 > 风险偏好 > 操作建议
```

| 情况 | 处理 |
|---|---|
| 政策比法律严（如通知期45天 > 法定30天） | ✅ 按企业制度执行，报告会标"严于法定" |
| 政策比法律松（如"员工辞职无需批准"） | 🔴 该条款无效，会提示你修订 |
| 政策表述过宽（如"三期一律不得解除"） | ⚠️ 会提示表述风险 |

## 九、拿到报告后怎么用

### 9.1 先看这三处

| 位置 | 看什么 |
|---|---|
| **结论摘要** | 总体判断能不能做、最大的风险是什么 |
| **待专业人员确认事项** | 哪些地方它不敢下定论——**这些才是你要重点问法务的** |
| **风险与建议汇总表** | 全局视图，按风险等级排序 |

### 9.2 再看证据清单

如果选了C选项或报告含证据清单，**那是给你的行动清单**：

```
✅ 已具备：考核制度（含民主程序决议）、2025年考核结果（已送达）
❌ 缺失：培训记录、员工签收表
   → 缺失后果：无法证明履行了第40条第2项的法定前置程序
```

**对照着补证据，比读法律分析更有用。**

### 9.3 提修改意见

直接说：
- "第3部分太笼统了，展开讲讲"
- "第5条的依据能再核实一下吗？"
- "建议部分要加上谁来负责"

它会按意见逐条处理，同步更新底稿。

**风险等级只在三种情况下调整**：出现新事实、找到新依据、你明确确认。
不会因为你觉得"应该没那么严重"就自动降级。

### 9.4 报告能直接给老板吗

可以，但注意：
- 报告已做**脱敏处理**（员工用代号、薪酬只给区间）
- 但**"待专业人员确认"的事项不要跳过**——那恰恰是最需要法务把关的
- 涉及**违法解除定性**的结论，**必须**先经律师确认

## 十、常见问题

**Q1：一定要联网查法条吗？会不会很慢？**
要查，而且不可跳过。劳动法规逐年变动，模型记忆不可靠。
没有权威检索工具时会降级为官方站点直取，并在报告里说明"未使用权威源验证"，关键结论标"需专业人员确认"。

**Q2：我的情况很简单，能跳过闸门直接出报告吗？**
可以，你明确说"直接出报告"就会跳过闸门一。
但**法条检索、知识层校验、"待确认"事项披露这三样不会省**。

**Q3：结论一定准确吗？**
不能承诺绝对准确。
系统通过五道防错降低风险：权威源核验、来源分级、时效核验、限定保留、知识层不可作依据。
但**劳动法高度依赖个案事实和地区口径**，涉及这两块的，一律标"需专业人员确认"。

**Q4：能不能用它直接写解除通知书？**
可以作为草稿参考，但**不要直接用**。
它的建议基于"合法性与风险"视角，不了解你公司的具体情况、证据状态和谈判态势。
**解除通知书发出前，务必经法务审核。**

**Q5：它会不会泄露我的员工信息？**
按 `data-handling.md` 规则：
- 员工姓名用代号，身份证/手机号不出现
- 薪酬只给区间，不给明细
- 病历只写"是否存在医疗期"，不写病种
- 你的制度包仅授权加载，跨客户不复用

**Q6：为什么报告里从来不写"根据我们的手册"？**
因为手册是企业内部文件，不是法律依据。
政策要求会出现在单独的「政策核对表」里，和法律依据分开呈现。

**Q7：没有 Python 能用吗？**
能。脚本全是**可选增强**。
没 Python 时：文档条款抽取→人工读原文；知识层体检→人工核对元数据；Word生成→只给 Markdown。
**主流程完全不受影响。**

**Q8：能处理多份文档吗？**
可以，一份一份给它，或用条款抽取脚本先批量过一遍。
脚本会抽取11类用工条款并标注风险线索（不是结论，仍需法条核验）。

**Q9：跨地区用工怎么定口径？**
按**实际用工所在地**（优先于注册地）。
多地各有员工 → 分别适用各地口径，不套用统一口径。
系统提供检索词模板和常见争点清单，但**地区口径每次都要实时检索**。

**Q10：我的员工在公司所在地工作，但公司在另一个城市注册，按哪边？**
按**实际用工所在地**。
这就是为什么报告里会问你"公司在哪个城市、员工在哪工作"。

## 十一、遇到问题怎么排查

### 11.1 它直接出报告了，没问问题

**原因**：你可能说过"直接出报告"，或者它误判了。
**解决**：明确说"先别出报告，我要先补充信息"。

### 11.2 报告里出现"未使用权威源验证"

**原因**：检索工具不可用（没装 MCP、或网络受限）。
**影响**：法条准确性未经验证，关键结论已标"需专业人员确认"。
**解决**：配置法律检索 MCP（flk-npc 或北大法宝）后重跑。

### 11.3 反复提示同一个"知识层差异"

**原因**：你还没采纳或还没改。
**解决**：让它帮你改那段内容 → 改完更新 `last-checked` → 跑检测脚本。

### 11.4 docx 没生成

**原因**：缺 `python-docx`。
**解决**：`pip install python-docx`，或直接选"仅 Markdown"。

### 11.5 知识层检测脚本报很多警告

**检查**：
1. 有没有文件超过180天没核验 → 正常，重新核验即可
2. 有没有文件缺 `confidence` → 补上
3. 有没有新加的文件没登记 → 补 frontmatter，或加进脚本的方法层白名单

### 11.6 报告结论和我的判断不一致

**这是正常的**，很可能它是对的。
建议你：
1. 看「依据」栏的法条原文
2. 去北大法宝或国家法律法规数据库自己查一遍
3. 如果你确认它错了 → 告诉它哪里错 → 它会重新检索

> **你和它有分歧时，永远以法条原文为准。**
